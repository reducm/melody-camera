# Melody 相机：让拍照成为两个人都开心的事

## 我们要解决什么

问题不只是“照片不够清晰”，而是摄影者不知道该站哪里、镜头怎么选、人物如何摆、背景如何避开；被摄者的偏好也往往没有被表达出来。产品主线是“拍前指导优先、拍后适度调整、始终保留选择权”。不承诺一键完美，不给外貌打分。

用户是摄影者和 Melody。首版以竖屏、后置摄像头、单人拍照为主。默认中文，无账号、无服务器、无需模型就能体验离线方案。

## 当前主流程（2026-10-03）

需求已经从首版人像练习扩展到人物、瓶罐、商品等实际主体。打开 App 默认后摄取景，拍照/系统相册选图进入持久拍摄项目；对单张照片用在线 DeepSeek 或本机 Gemma 生成详细观察与多个模板，选模板继续跟拍，新照片留在同一项目；历史可继续编辑。

Vision 提取实际主体轮廓，当前模板等比摆位并给机位提示。参考图开启时，此 iPhone 内的 Draw Things / Qwen Edit 异步生成低清参照，模板可先拍。全屏看图、来源标签、自动/手动名称、原片/副本保存、模板回看与本机分级日志均已实现，验收边界见 [本次会话总结](会话总结-2026-10-03.md)。摄影知识、新视角目标轮廓、实时对齐和全流程进度仍待实现。

以下保留早期完整体验设想和版本计划，不能当成最新进度；尤其“未编译/未接模型”已被本次实现替代。早期多倍率自动观察不是目前拍照后单图推荐的主入口。

## 完整体验设计

1. 打开取景。画面优先，相机权限在使用实景相机时请求，拒绝后仍可体验练习场景或导入照片。
2. 点击“看看怎么拍”。在明确允许上传或安装好端侧模型后，采集少量不同倍率画面；提醒人物短暂保持不动。采样结束恢复之前的倍率。
3. 给出三种方向，例如“留一点风景”“靠近一点点”“走进画面里”。每种包含机位动作、人物位置、倍率及理由，不给十条难执行的建议。
4. 点击卡片应用倍率并显示人物目标轮廓、九宫格。首版是静态目标；后续用 Vision 比较实际人物位置，按顺序只提示最重要的一个动作。
5. 用户自己决定拍摄时机。后续可加短连拍、眨眼提醒和“这一张不错”的候选推荐，未经点击不自动保存到相册。
6. 进入照片处理，先展示自然调色，允许强度调整、原片对比、单独保存原片与副本。
7. 后续加入 Melody 的私有偏好：“自然肤色”“喜欢全身照”“不瘦脸”“不要磨掉雀斑”。先由她选择，再让推荐学习；不是偷偷自动上传历史照片训练。

## 为什么先不做“完美美化”

OpenPose 给出骨架关键点，并不生成人脸或修复眼睛。姿态检测适合“如何站”“轮廓有没有对齐”；皮肤处理需要人脸区域掩膜、保边滤波；补睁眼需要另外的图像生成/修复模型，最好有同一人的相邻帧作为参考。视觉语言模型分析图片，也不意味着它能返回修复后的图片。

首版的调色是真实像素处理，但不是皮肤磨皮、脸型重建或 AI 生成。生成式修复要独立建设身份保持、局部掩膜、结果对比、取消与撤销，不将一次模型生成直接覆盖原片。

## 额外值得做的点子

- **一句话导演**：一次只说“手机稍微放低”，而不是同时显示一屏参数。可选语音，由用户开启。
- **从连拍中选好的一张**：眨眼、运动模糊、表情、画面边缘截断，先用可解释的指标，避免外貌评分。
- **Melody 确认的模板收藏**：她喜欢的照片只提取构图关系与偏好，不必须永久存储原图或上传。
- **两个人的回放**：拍完只需点“更喜欢 A / B”，下一次优先相同构图与调色。
- **拍摄环境提醒**：逆光找补光面、树影避开脸部、背景线不要穿头；不强迫用户学习 ISO 等术语。

## 非功能要求与验收目标

目标不是未经实测的性能承诺。真机阶段测量取景流畅度、点击到结果时间、每次分析的内存峰值、温升、能耗、图片上传大小及成本。AI 不应阻塞快门；首版采样期间暂时禁用快门，后续用独立预览帧管线改进。

必须验收：无网络能拍/能导入；拒绝权限不崩溃；在线失败有错误、不伪造成功；取消后不显示过期结果；原片不被覆盖；无能力的倍率不出现；叠加框不进入保存照片；模型输出非法不渲染；竖屏预览与保存朝向一致。模拟器不能证明真实多摄、自动对焦、热状态或成像质量。
