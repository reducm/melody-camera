## 现在就能运行：Mac 拍摄练习室

在项目目录的终端执行：

```sh
./scripts/run-mac.sh
```

脚本编译同一套 SwiftUI 代码，在 `.build/MelodyCamera.app` 生成本机临时签名的 App 并打开。它提供练习场景、离线建议、构图叠加、照片导入、在线模型设置与调色/导出。没有冒充 iPhone 摄像头，也不是 iOS 模拟器。第一次钥匙串访问可能由 macOS 弹出系统询问；没有密钥也可以使用全部离线功能。

建议体验：点击中央快门生成练习照片，或选择照片 → 进入拍摄项目 → 查看/生成推荐、切换照片与编辑配方 → 原片对比与导出。Mac 练习画面明确标为非实拍，Gemma/Qwen 的手机运行时不能用 Mac 练习版代验。

## 安装 Xcode 后运行 iOS 模拟器

1. 使用自己的 Apple Account 从官方渠道安装与 macOS 兼容的 Xcode，首次打开完成系统提示。
2. 在 Xcode Settings 的 Components/Platforms 中只装一套 iOS Simulator，先不要安装全部平台。完整 Xcode 和运行时是 GB 级，保留足够空间。
3. 如果命令行仍指向 CLT，在 Xcode 的 Locations 中选择 Command Line Tools 为刚安装的 Xcode。也可自行执行 `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`。
4. 执行 `./scripts/run-ios.sh` 打开工程，选一个已安装的 iPhone 模拟器，按运行。
5. 模拟器无需付费开发者账号或真机签名。iOS 默认尝试实景取景；模拟器没有相机时显示说明，可从系统相册导入，不能把 Mac 的演示按钮当作 iOS 的默认流程。

无签名编译检查（有完整 Xcode 和 iOS SDK 后）：

```sh
xcodebuild -project MelodyCamera.xcodeproj -scheme MelodyCamera \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath DerivedData CODE_SIGNING_ALLOWED=NO build
```

当前已实际运行并通过 iOS 构建；Mac 的 swift build 仍不能替代它。

## 安装到 iPhone 17 Pro Max

确认手机的实际 iOS 版本，并选择支持该设备调试的 Xcode；必要时先安排 Mac 系统升级。用户自己的 Apple 登录、系统升级及设备信任要由用户完成。

1. 在 Xcode Settings → Accounts 登录 Apple Account。
2. 数据线连接手机，在手机上信任电脑，并按系统要求开启 Developer Mode。
3. 工程 Signing & Capabilities 选择 Personal Team，保持 Automatically manage signing。
4. 若 `com.melody.camera` 被占用，改成个人唯一 Bundle Identifier，例如 `com.yourname.melodycamera`。
5. 选择自己的 iPhone，运行。打开 App 默认进入取景，允许相机权限；底部中央快门拍照。
6. 免费 Personal Team 有短期 provisioning 限制，通常需要每 7 天重新签名/安装。首次无需购买会员。[Apple 免费账号说明](https://developer.apple.com/help/account/basics/about-your-developer-account)、[运行到设备](https://developer.apple.com/documentation/Xcode/running-your-app-on-simulated-or-physical-devices)。

TestFlight 是以后给 Melody 方便安装/更新的一种方式，需要开发者计划与上传流程；不是当前自用调试的必要条件。本次没有创建 TestFlight 发布。

## 开发命令

```sh
swift test                       # 领域、图像与 Mac 应用流程测试

```

生成的工程已入项目，不强制每个使用者都先安装 XcodeGen。脚本、源码不包含模型 Key；不要把个人模型、照片、证书和 `.env` 提交到 Git。

## Python 开发者的 Swift 入门路线

先看 `Sources/MelodyCore/Composition.swift`：`struct` 类似不可变 dataclass，`enum` 为有约束的选择，`throws` 为可传播错误。再读 `VisionDirector.swift` 的请求/JSON 校验，然后读 `StudioModel` 的 async/await 流程。最后进入 SwiftUI 与 AVFoundation；不需要同时学习 Objective-C。


## 模型依赖与代理

Xcode 工程用 SPM 固定 Google LiteRT-LM 0.16.0；使用官方 iOS arm64/模拟器 arm64 二进制，Intel 模拟器不受支持。首次检出需要 Git LFS，本机已安装。解析源码时可用 `GIT_LFS_SKIP_SMUDGE=1 xcodebuild -resolvePackageDependencies -project MelodyCamera.xcodeproj -scheme MelodyCamera`，跳过上游测试模型大文件。

本机下载超时时按用户偏好使用 Clash：`proxy_on` 定义在交互式 zsh 配置，指向 localhost HTTP 代理。自动化 shell 可执行 `zsh -ic 'proxy_on; <下载或依赖命令>'`。不更改系统代理设置，不将模型 Key 发送给下载站点。

Gemma 模型不进应用包和 Git：在模型设置导入指定 .litertlm，按 ADR 002 的大小和 SHA-256 校验后保存在应用支持目录。Mac Swift Package 构建不链接 LiteRT-LM，不能以 Mac 测试证明手机推理可用。Debug 的 `--melody-check-gemma` 只读取开发者显式拷入容器的公开测试文件，结果不含 Key 或图像正文；普通启动不运行该检查。

## 当前 Draw Things 构建与模型

Xcode 工程还固定 `_MediaGenerationKit`，版本和内存策略见 ADR 005。Gemma 约 2.59 GB、Qwen 整套约 28 GB 已通过当前个人开发设备容器安装；模型不随安装包或仓库复制，卸载 App 会丢失模型和项目。普通用户下载器仍是待办。

当前已有完整依赖缓存的构建目录是 `artifacts/drawthings/ios-probe/DerivedData`（被 Git 忽略）。在本机可优先复用；新机器不依赖该路径存在，按固定依赖重新解析。对同一个 DerivedData 的真机与模拟器构建应顺序执行。Xcode 工程的 `Package.resolved` 必须提交，以保留固定的实际依赖版本。
