# 摄影知识与推荐模型调研

调研开始：2026-10-03；开发交接：2026-10-04。对应分支：`codex/knowledge-guided-recommendations`。本轮完成源码开发，用户要求构建与设备验收后续再做。以下外部研究结果不代表 Melody 的实测效果。

## 需求与结论

目标是结合实际主体、图像观察和用户选择的拍摄风格，给出摄影依据明确、现场可以尝试的构图方案，输出操作步骤和可跟拍的目标。生成图片只是帮助表达目标，不能以“生成成功”代替拍摄建议有效。

首版采用 **结构化视觉观察 → 本地摄影知识检索 → 有约束的构图搜索 → 目标轮廓 → 参考图核对与选用**。当前不训练新的视觉权重，不接入远程数据库，不下载摄影作品集。知识卡和规则保存在 MelodyCore，具备版本、来源和回归用例。小规模知识集合用有类型的只读目录即可，后续内容量与编辑需求增长时再迁移 JSON/SQLite；存储格式不决定推荐质量。

## 为什么本轮选择知识与规则组合

只有提示词：开发简单，但每次由模型自由给坐标，缺少稳定约束和可回归的摄影依据。现有方案已经暴露“换框而不换形状”的问题。

只有摄影数据库：可以找到知识，却不自动产生目标几何，也不知道现场是否有桌面、背景或足够移动空间。必须把知识条件与当前观察连接起来。

只有美学/裁切模型：适合比较已有画面或选裁切，不足以设计拍摄动作。某个裁切得分更高不能证明移动相机会产生相同效果。

完全自训：需要有许可的样本、摄影者动作、拍前拍后关系、风格偏好和评价。当前没有这套项目数据，直接训练会把“评分看起来专业”放在“现场建议有效”之前。

本轮方案把视觉模型用于语义观察，知识规则负责适用性和可解释性，候选搜索负责目标位置与比例，几何/生成分支负责形状。其代价参数是项目工程启发式，并非书籍给出的普适最优值，必须通过后续照片对照校准。

## 后续书籍与自有资料如何进入

用户提供资料后，先登记书名、作者、版本、页码、可用范围；由人工或模型辅助改写成原创知识卡，再审核适用主体、前提、禁用条件、动作和反例。不要把整本书的文本直接塞入每次模型调用。引用保持可追溯；书中照片的展示/训练许可独立处理。

每新增卡片同时提供可运行场景测试：应触发的案例、应拒绝的案例、与其他技巧冲突的案例、缺少观察信息的退化结果。先扩充内容质量，再考虑向量检索。未审核资料不能直接影响默认推荐。

## 自有模型的升级路径

1. 建立经用户同意的本机研究样本：原片 ID、场景观察、风格、候选方案、选中项、实际跟拍、明确反馈。当前已保存批次和跟拍方案快照；独立反馈标注与训练导出尚未实现。
2. 用同一来源照片拆分训练/验证/测试，避免同场景近重复图跨集合；身份、环境与风格均需要覆盖。
3. 首先评估轻量的候选排序模型，而不是从头训练图像生成模型。规则继续负责硬约束，学习模块只帮助排序。
4. 用基线对照判断收益：当前旧方案、知识规则 v1、加入检索/重排的候选，分开衡量建议合理性、操作可执行性、主体保真和用户选择。
5. 只有实际收益与端侧资源测量成立后，再考虑蒸馏、Core ML/其他端侧适配；不把论文结果写成本项目性能。

本轮没有新增付费服务、下载研究权重、上传私人照片或训练模型。
