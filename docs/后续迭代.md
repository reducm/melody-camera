# 后续迭代清单

按价值与依赖排序，而非先追最大模型。

## 第一优先：让手机上的基础拍照可靠

- 安装合适 Xcode，执行 iOS 编译，修复实际 SDK 差异。
- 模拟器回归：布局、导入、权限拒绝路径、在线超时/取消、照片保存提示。
- iPhone 真机：相机授权、首次启动、0.5/1/2 能力与映射、预览和保存方向、全画幅一致、返回后台、来电中断恢复。
- 真机确认每次三倍率采样在完成/取消/错误后恢复倍率，不将采样照自动保存到相册。
- 修复生成式修图之前，先补高分辨率后台导出、内存上限和导入大图异步解码。

完成标准：离线可以连续拍摄与导出，原片不丢失；无崩溃、无伪造成功。

## 第二优先：验证一个真正的视觉 provider

- 用户填写自己的视觉模型和 Key，使用一张非隐私测试图请求。
- 核对该模型能理解画面而不是只读提示；测试多图、结构化方案、429、401、错误 JSON、取消。
- 测量成功率与用户等待时间，选择是否加 provider 专属参数（如禁用推理、token 上限等）。
- 将固定响应测试与真实测试分开，真实测试不进默认 CI，不将密钥写入快照。

## 第三优先：先几何感知，再上端侧大模型

- 用 Apple Vision 检测人体/人脸，把检测范围转换成统一左上坐标。
- 给“向左一点/手机放低/背景太挤”等单一反馈；低置信度不提示“对齐成功”。
- LiteRT-LM 小型多模态模型做单图 PoC，固定模型版本与文件校验，记录真机温升、耗时、内存。
- 对比离线规则 + Vision、端侧 Gemma、在线视觉三者质量，再决定默认模式。

## 第四优先：Melody 看得见的收益

- 3–5 张短连拍优选：模糊和眨眼，保持身份和原始质感。
- 明确同意下保存风格偏好和收藏模板。
- 使用人脸掩膜局部处理肤色与细节；不过度磨皮，不改脸型默认值。
- 生成式睁眼采用同一人参考帧、掩膜区域、结果对比；失败保留原片并提示。

## 未解决的问题（可等首次体验后决定）

- 最常见的是全身、半身、旅行还是室内？优先按真实偏好挑模板。
- 是否接受照片离开手机？若不能，优先投资 Vision + 本地模型。
- Melody 更重视“像本人”还是某种风格？此选项由被摄者选择。
- 常见的低光场景、是否需要前摄/横屏、是否接受连拍等，均影响后续相机管线。
