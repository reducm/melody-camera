# 后续迭代清单

## 2026-10-04：知识推荐 v1 已进入自动回归

Swift 测试、Mac 构建、iOS 模拟器构建与公开照片流程已执行，详见 [本轮总结](会话总结-2026-10-04.md) 和 [验证记录](验证记录.md)。本机无可操作真机、Mac 锁屏导致 UI 点击受阻；不将程序内流程检查当手势验收，固定场景与快门替身不当真实模型或相机结果。

当前优先补真实模型新 scene 合约、生成图轮廓的界面核对与真机摄影质量；既有已配置模型和登录不从零重做。以下长期目标以现有实现为基础。

## 已完成的基线

- 新机 Xcode/iOS 组件、Personal Team 签名、模拟器与手机无线安装；用户确认实景取景拍照。
- 系统 PhotosPicker、Vision 真实主体轮廓、DeepSeek/Gemma 详细照片分析与可选模板；新照片/历史不会自动上传。
- 默认取景、中央快门、持久项目、多照片/多批次、模板跟拍来源、独立编辑配方、历史继续编辑。
- 取消上传开关、直接展示轮廓、自动/手动标题、照片来源标签、全屏分页/缩放/下拉、原片/副本保存和模板回看。
- 真机切换 0.5/1/2 倍率不丢模板；手机 Qwen Edit + Lightning 真实出图及恢复；全局四档尺寸已接入。
- 本机分级日志、模型文字输入输出、关联生成图、筛选和清理；历史 77 项测试及两个 iOS 编译通过；本轮回归结果见最新验证记录。已实现不等于下面每个真机待验项已经通过。

## 第一优先：手机体验与数据可靠性

- 真机连续拍摄、权限拒绝、预览/保存方向与画幅一致、返回后台和来电中断恢复。
- 验收原片/调色副本在系统相册中的实际结果、拒绝 addOnly 权限、保存失败与重复点击。原片保持字节不变，模板不写入导出照片。
- 全屏左右翻页、下拉短拖回弹、放大时拖动不误退出/误翻页；模拟器只完成按钮分页与返回，不能替代这些手势。
- 多倍率顺序采样在成功/取消/失败后恢复倍率，不将采样图自动保存到相册。
- 历史长期恢复、存储不足与损坏隔离；历史删除、整项目导出/迁移格式尚未提供。高分辨率后台导出与大图内存预算仍待做。

完成标准：离线连续拍照和导出可靠、原片不丢；失败明确可恢复，不伪造成功。

## 第二优先：本机参考图的资源和质量

手机已能实际生成，不再从“是否能出图”重复开始。当前仅 512×512 / 4 步有真机出图证据，参见 [ADR 005](adr/005-iPhone端侧参考图.md)。

- 逐项验收另外三个尺寸、飞行模式、连续批量、低电量/发热/内存压力、生成途中取消、后台与相机拍摄并行场景。记录实际耗时与资源，不能套用厂商或 Mac 基准。
- 建设普通用户模型下载器：空间检查、断点续传、取消、哈希校验、版本迁移与完整性显示；当前设备容器复制不等于通用安装管理。
- 在保持 Gemma/Qwen 串行的基础上设计热状态与低内存退让；暂停/重启/重试要与任务状态一致。
- 瓶罐、人物、透明反光、复杂背景样本比较主体身份、标签文字、背景保留、机位和留白。Lightning 已采用；Multiple-Angles LoRA 尚未实验，需单独对照再决定组合。
- 参考图与原片并排比较、按原画幅选择尺寸可后续增加；将生成图提取为设计轮廓前，先做质量与来源校验，不自动替换正在跟拍的模板。
- 云改图供应商可实现现有 `ReferenceImageGenerating`，目前未实现；需要独立配置、钥匙串和明确数据目的地，禁止本机失败自动上传。Mac 服务不再是产品待办。

## 第三优先：摄影知识与新目标轮廓

用户认为这是核心技术，接受当前简单模板，但要求持续推进完整设计。详见 [推荐引擎架构](推荐引擎架构.md)。

1. 首批 10 张自有知识卡与规则检索已完成；接下来用真实失败样本调整适用条件、动作前提与风格差异，再决定是否需要案例或向量检索。
2. 瓶罐/盒体/平面物件的有限类别几何已实现；人物姿态骨架与真实新视角恢复尚未实现。生成图描边须人工核对选用。
3. 已有技巧条件、方案几何去重和来源校验；需进一步实测摄影可执行性，同照片跨轮的推荐偏好与质量去重尚未完成。
4. 新轮廓可靠后，接 Vision 跟踪/人体关键点，低频提示一个最重要动作；不把简单框重合显示成拍得好或角度正确。
5. 按需引入有许可的案例库、目标偏好和前后照片反馈，模型 SDK 仍与 Core 隔离。

Meta EdgeTAM 仍是描边质量候选，尚未集成；只有系统分割的样本结果说明不足时才引入，不因已有转换脚本就认定可直接使用。

## 交互要求：统一进度（部分实现）

用户要求分析、loading 等采用百分比进度条，允许先记录后实现。当前 Qwen 采样用实际步数、模型文件就绪用实际字节；其他入口仍未统一。

- 覆盖照片导入、主体提取、模型安装/校验/加载、分析与保存，提供阶段、取消、失败与重试。
- 有总量才计算百分比；在线 API/模型加载无回调时显示真实可确认阶段和等待时间，不能编造“完成 80%”。若估算，必须标注预计。
- 采样 100% 不能代表解码保存完成；旧任务不能覆盖新进度，取消/失败不能冒充完成。

## 模型和日志后续验收

DeepSeek Flash 和 Gemma 均已完成公开样图真实调用；不再将“寻找第一个可用 provider”作为从零任务。

- 增加瓶罐、人物、遮挡、多主体、多画幅等非隐私样本；结构合法不代表推荐正确。分别测合约通过率、建议差异、边缘质量和等待时间。
- 在线多图、401/429、错误 JSON、超时/取消继续区分固定响应测试与真实服务测试；真实调用显式开启，不进入默认 CI。
- 在日志版本补验实际在线/Gemma 输入输出；Qwen 真实日志关联和重启恢复已通过。
- 清理按钮的系统确认框与清空后继续产生新事件待 UI 点测；逻辑和独立目录真机清理已经通过。时间轮转有注入时钟测试，未做自然等待七天/强制断电。
- 日志导出、MetricKit 或崩溃汇总可按排错需求另做，当前无后台上报。模型正文开关关闭只影响之后提交的文字，历史正文要通过清理移除。

## 后续产品收益与待决定问题

- 3–5 张短连拍优选：优先模糊、眨眼等可解释指标，不给人物外貌打分。
- 被摄者主动选择的风格、模板收藏和反馈；不自动上传历史训练。
- 温和局部肤色处理、带参考帧的睁眼修复分别设计掩膜、身份保持、原片对比与撤销；不将现有调色说成这些功能。
- 更常拍全身/半身/旅行/室内，是否需要前摄/横屏/连拍，后续结合用户真实偏好决定。当前在线/本机的上传选择已有明确交互，不重复索要会话许可。
