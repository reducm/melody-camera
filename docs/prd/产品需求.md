# Melody 相机产品需求讨论稿

版本 v0.1 · 2026-10-04 · 面向产品讨论与后续实现。当前实现依据 `codex/knowledge-guided-recommendations` 工作区、[最新会话总结](../会话总结-2026-10-04.md) 和 [验证记录](../验证记录.md)。本稿不改变 App 行为。

Melody 帮助摄影者从一张现有照片得到可以执行的下一张拍法，通过模板返回相机，在同一项目内不断拍摄、回看和调色。当前重点是把这个循环做可靠，而不是承诺自动拍出好照片。本文和 [页面规格](页面规格.md)、[流程图](页面流程图.md) 一起构成可持续修改的产品基线。

## 1 产品目标与用户场景

主要用户是想给喜欢的人或物拍得更好的摄影者；被摄者可以参与选择喜欢的风格。现有场景已从单人人像扩展到瓶罐、商品、食物、多人和环境，但不同类别的实际推荐质量仍待验收。

| 用户问题 | 产品回应 | 如何判断是否有效 |
|---|---|---|
| 不知道下一步怎么移动和取景 | 观察照片，给出 1–3 个有条件、有顺序的拍摄模板 | 用户能理解动作并在现场执行；记录无法执行的原因 |
| 拍了新照片就丢掉前面的建议 | 同项目保留多张原片、每张多轮推荐和跟拍快照 | 历史恢复后来源、配方和当前照片一致 |
| 文案难以想象 | 显示目标范围、来源明确的轮廓及可选 AI 参考图 | 能区分实拍、原片轮廓和设计示意；不被误导为真实新视角 |
| 想调整色彩又怕破坏原片 | 可撤销调色，保存独立副本 | 原片字节不变，导出不带模板线 |
| 不想把私人照片自动传出去 | 本机处理；在线仅在选择在线并主动生成时上传压缩图 | 拍摄、导入、切换与恢复均不产生分析上传 |

当前不设未经测量的转化率、审美分数、成功率或耗时目标。后续用同一组非隐私样本做人工对照，分别记录建议可执行性、风格差异、主体完整性和跟拍偏好；测试设计不等于已有收益结论。

## 2 范围与状态

| 范围 | 当前实现 | 验证边界 |
|---|---|---|
| 后摄竖屏、取景、拍照和可用倍率 | 已实现；默认打开相机 | 历史有用户确认拍照和倍率检查；连续拍摄、中断、画幅、权限仍需真机补验 |
| 项目、多照片、多批次、命名、历史 | 已实现；本机持久化 | 公开照片流程和恢复已验；长期存储不足/损坏的现场恢复仍需补验 |
| 在线 DeepSeek、本机 Gemma 分析 | 已接入并有旧版公开样图真调用 | 最新结构化观察合约和 Gemma 上下文变更尚未真模型复验 |
| 摄影知识推荐 | v1 已实现，4 风格、10 知识卡、1–3 个方案 | 单元与公开样本流程已验；摄影收益未证实 |
| 模板轮廓 | 原片摆位、类别几何、仅范围、核对后的生成图轮廓 | 真机复杂主体、角度/身份准确性仍待验；不提供 3D 重建 |
| iPhone 内参考图 | Qwen Edit + Draw Things 已接入，逐个排队 | 旧版 512 方图真实生成与恢复通过；新轮廓链路、其他尺寸和压力待验 |
| 调色和大图查看 | 已实现，原片与副本分开 | 像素/文件与按钮分页已验；缩放、翻页、下拉的手势冲突待验 |
| 设置与本机日志 | 已实现，Key 进钥匙串，四级日志和正文开关 | Qwen 日志/恢复有证据；在线/Gemma 新调用日志及清理确认点测待补 |

Mac 是练习环境，演示画面必须注明非实拍；离线摄影规则不是本地大模型。当前 iPhone 照片分析入口提供在线与 Gemma，两者不可用时仍可拍摄、导入、回看和调色；不把未暴露的离线推荐入口写成现有替代路径。

已撤销：Mac 中转生成作为产品路径；独立上传许可开关。当前不提供账号、云同步、自动上传训练、自动美颜、自动按快门或自动成功评分。前摄、横屏、通用人体姿态合成、云改图未纳入当前已实现范围。

## 3 信息架构与导航

核心只有两个一级工作面：P01 相机和 P03 项目。相机中的模板跟拍状态单列为 P11。P03 内含主体 P04、分析 P05、报告 P06、模板 P07、参考图 P08、调色 P12；将其单列编号是为了讨论，不表示七次页面跳转。

系统相册 P02、历史 P14、设置 P15、命名 P20、错误 P21 是从当前工作面打开的系统界面或弹层。照片大图 P13、AI 参考图大图 P09 和轮廓核对 P10 是不同用途的查看界面。设置内含在线 P16、本机模型 P17、日志 P18 和详情 P19。

主路径：P01 → 拍照或 P02 导入 → P03 → 选择主体/方式/风格 → P05 → P06/P07 → P11 → 新照片追加 P03。P08→P09/P10 是推荐的并行附件，等待或失败不会阻断 P07→P11。

所有页及状态的入口、出口、数据和验收详见 [页面规格](页面规格.md)。现状图使用实线；规划图使用虚线，并明确标记规划。

## 4 核心产品规则

### R01 项目与照片

第一张成功拍摄/导入的照片创建项目；之后拍摄、补拍、相册导入和模板跟拍都追加到当前项目。只有用户主动新建才开始另一个项目；新建不删除旧项目。保存失败显示待重试，并阻止用户直接用新建丢开未保存项目。项目不自动同步，卸载会删除本机历史。

每张照片保留原始文件、独立调色配方、历次推荐和可选跟拍来源。切换照片恢复它自己的报告、批次和配方。自动命名可随新一轮主体名称更新；手动名称最多 100 字、去除首尾空白后非空，之后不被模型覆盖。

### R02 分析触发与风格

“自然纪实、环境叙事、简洁留白、主体质感”影响下一轮拍摄推荐，不等于照片调色。选择主体也只影响下一轮。生成时固定项目、照片、主体、风格与可用倍率；生成期间防重复触发。取消、切换来源或离开后不接受迟到响应。

在线必须先校验地址、模型和 Key。只有用户选择在线并主动点击生成推荐才发送当前原片重新编码的压缩图；不额外设置上传开关。Gemma 缺模型时明确引导到设置，失败不自动改用在线。模型返回观察后由本机知识规则给出最终模板。

### R03 报告与模板

报告包含概述、优先动作、光线、构图、背景、姿态/摆放、成像与判断边界，展示来源，不给审美或外貌评分。成功生成新增一个推荐批次；失败保留旧报告和旧批次。模板可少于三项，不为凑数制造重复。相同输入跨轮可能得到相似建议，不能承诺每轮不同。

每个模板显示标题、可用倍率、轮廓/范围来源、机位动作、理由、步骤和适用条件。原片轮廓摆位只做等比变换；类别几何是筒体、盒体或平面物体的受控示意；没有可靠信息时只给目标范围；AI 参考图轮廓必须经过核对。四种来源不能混称“真实识别”。

### R04 手机参考图与核对

当前源码中“生成推荐时同时生成参考图”初始开启；这是参考图开关，不是上传许可开关。推荐成功后，在此 iPhone 内逐项生成附件；用户可关闭自动参考图，也可取消、重试单任务。Gemma 与 Qwen 共用本机模型槽，排队不得显示成已经采样。

默认 512×512，可选 512×768、768×512、768×768。修改影响之后提交的任务，已提交任务保留配置。图像始终标“AI 生成参考 · 非实拍”，可能改变细节；失败时模板继续可用。不能把旧 Mac 图混作手机生成结果。

生成图得到完整候选轮廓后可进入 P10，按中央 3:4 取景区域显示。用户选择主体，并分别核对身份/数量/细节、轮廓/角度/构图、现场动作可执行，三项全部满足才能选用。换候选重置核对。核对只是用户判断，不是系统认证。

选用后更新下一次跟拍的轮廓和相应文案；可以恢复知识模板。重新生成要重新核对。已经拍下的历史快照不随撤回或重新生成而变化。无完整轮廓时保留参考图查看功能，继续使用原知识模板。

### R05 跟拍与真实相机

应用模板先验证相机与设备倍率，成功才返回跟拍取景；失败留在项目。只显示设备可用倍率，不能承诺每台设备都支持 0.5/1/2，也不能把倍率等同于独立物理镜头。用户手动换倍率保留模板和来源，不改写模板本身的推荐倍率。

用户主动按快门，照片加入同项目并保存当时方案快照。当前没有实时位置误差、角度校验、对齐成功或审美评分。用旧模板拍新照片后显示的轮廓是历史目标，不是对成片的新检测。无参考图或分割失败都不应禁用可用的普通拍摄。

### R06 调色、查看与保存

调色只更新配方和副本，原片不变。原片对比不改写配方。保存原片保留原始格式，保存调色副本为重新编码 JPEG，不带模板和原 EXIF/GPS。当前副本使用预览处理尺寸，导入最长边 2400、真机 4096；全分辨率导出尚未提供。

保存系统相册需 addOnly 权限，防重复点击，成功/失败都有反馈；拒绝不删除项目。大图缩放时拖动看局部，恢复原比例后才能正常翻页和下拉退出；退出后项目定位到最后查看照片。此手势规则已编码，但仍待真实手势验收。

### R07 进度、错误与中断

可测总量才显示百分比。Qwen 采样百分比来自实际步数，100% 不等于解码/保存完成；模型文件就绪比例不代表下载进行中。在线无进度回调时用“正在分析”等真实阶段，不伪造整体完成度。统一多阶段进度仍是 F01。

错误至少说明受影响动作、是否保留原数据、下一步。当前通用弹窗多为“知道了”，部分重试在原入口；“错误弹窗直接跳设置/重试”属于本稿建议，不能描述为现有行为。后台会取消或中断当前任务并停止相机，恢复不得把旧回调写给新照片；具体参考图恢复状态按持久任务检查，不承诺后台继续生成。

### R08 设置、日志与模型边界

Key 只保存钥匙串。设置文件、项目历史与日志不含 Key；上传图去定位。模型输出需验证坐标、文本长度、重复 ID、可用倍率；UI 只绘制受控图形，不执行模型代码。

按既有用户要求，模型调用文字默认写本机日志，可关闭后续正文或清理历史。日志按 Debug/Info/Warning/Error 与功能筛选，可查同次调用和关联生成图；不记录密钥、图像正文或 EXIF 定位，不自动上传。清理仅针对 App 自己的日志，不删除项目或模型；关闭记录不能自动抹掉旧正文。

## 5 共用状态与验收场景

以下是必须保持的验收条件，不代表本轮重新执行过。证据级别逐页列出；代码、模拟器流程、UI 点测、真机、真实模型互不替代。

| 编号 | 场景 | 预期结果 |
|---|---|---|
| A01 | 首次打开、相机拒绝或不可用 | 说明状态，允许选图，不显示可拍摄假预览 |
| A02 | 拍照/导入后继续补拍 | 所有原片留在同项目，照片标签和数量正确 |
| A03 | 在线未配 Key 点击生成 | 网络前失败，旧批次不动；补配置后用户手动重试 |
| A04 | 只导入、切换、恢复历史 | 不发照片分析请求，不自动上传 |
| A05 | 多主体/无轮廓 | 可选可靠主体；无结果时明确降级，不捏造描边 |
| A06 | 分析取消、超时、非法 JSON | 丢弃迟到/非法结果，保留旧批次，可以再试 |
| A07 | 切风格再生成两轮 | 新批次保存新风格，旧批次保持原样 |
| A08 | 参考图排队、失败、取消 | 普通模板仍能应用，相互状态不冒充完成 |
| A09 | 参考图尺寸改变 | 旧任务尺寸不变，新任务采用新设置 |
| A10 | 核对缺一项/换主体/换任务 | 不可选用或要求重新核对；无错误身份认证表述 |
| A11 | 核对后跟拍再撤回 | 下一次模板改变，已拍摄快照保持当时方案和文案 |
| A12 | 跟拍中切换实际倍率 | 目标描边和来源仍在，不把不可用倍率交给相机 |
| A13 | 调色、原片对比、保存副本 | 原片字节不变；每照片独立配方；导出无模板 |
| A14 | 相册保存拒绝/失败/连续点击 | 明确错误、防重复、项目不丢，不伪造保存成功 |
| A15 | 全屏缩放/翻页/下拉 | 手势无冲突，退出定位最后照片；需实际点测 |
| A16 | 手动改名再生成 | 手动名称保留；空白和超长名不能提交 |
| A17 | 关闭日志正文、再调用、清理 | 新正文停止记录，旧正文要清理；项目不受影响 |
| A18 | 后台、中断、存储失败、历史损坏 | 有提示与可恢复路径，旧数据保留；恢复边界分别实测 |

## 6 后续模块与优先级

优先级是本稿建议，不是交付承诺。先保稳定，再扩能力；完整条目沿用 [后续迭代](../后续迭代.md)。

| 编号 | 模块 | 建议顺序 | 当前边界 |
|---|---|---|---|
| F01 | 所有耗时任务统一阶段与进度 | 高 | 已有部分真实进度，其余未统一；不能补假百分比 |
| F02 | 普通用户模型下载和管理 | 高 | Gemma 文件导入和校验已有；Qwen 容器复制不是用户下载器 |
| F03 | 实时跟拍动作提示 | 验收基础质量后 | 静态模板已有，实时几何反馈未实现 |
| F04 | 短连拍与选片 | 后续 | 先比较模糊/眨眼等可解释项，不给外貌评分 |
| F05 | 偏好、模板收藏与反馈 | 后续 | 没有偏好档案/收藏；用户主动选择，不上传历史训练 |
| F06 | 局部生成式修复 | 后续 | 调色已有；掩膜、身份保持、版本对比和撤销须另建 |
| F07 | 项目删除、备份与迁移 | 待排期 | 当前只有本机历史和单图保存；删除需防误删，迁移须定义格式 |

## 7 待讨论的产品选择

| 编号 | 问题 | 当前情况 | 本稿建议与代价 |
|---|---|---|---|
| Q01 | 项目页要不要拆独立报告/模板页 | 目前在同一滚动页，已有推荐/编辑切换 | 先保留一页，把报告默认折叠；减少跳转，长内容仍需优化 |
| Q02 | 参考图是否默认随推荐生成 | 当前初始开启，自动逐模板排队 | 讨论改为仅选中模板后生成，减少等待与资源占用；会多一步操作 |
| Q03 | 先给用户哪种分析方式 | 现有在线与 Gemma 可选 | 保留用户选择，明确配置/就绪状态；不做静默切换 |
| Q04 | 生成图核对是否加原片并排对照 | 当前核对页展示生成图 3:4 与三项确认 | 建议增加随时查看原片，便于核对；需设计小屏布局与内存预算 |
| Q05 | 跟拍时显示多少信息 | 当前标题、动作、模板与倍率 | 优先一个主要动作，其余展开；实时反馈实现前不显示“已对齐” |
| Q06 | 历史如何避免误新建和数据丢失 | 新建直接回空相机，旧项目保留 | 讨论增加轻提示和备份入口；先验收保存失败保护 |
| Q07 | 下一轮先做什么 | 手机交互、真实模型新合约与生成质量尚待验 | 建议先验收 A03/A06/A10/A11/A15，再统一进度与模型管理 |

本稿尚未收到对这些新增建议的确认。讨论结果应写入本节与修订记录，再变更实现，不能因线框展示就当作通过评审。
