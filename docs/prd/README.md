# Melody 相机产品评审入口

更新：2026-10-04。版本：v0.2 截图评审稿。本文档包用于我们持续讨论页面、流程与需求，不代表已批准的改版或新一轮 App 验收。

- [打开交互评审稿](评审稿.html)：流程节点附模拟器截图，拍照/跟拍用公开照片代替；点击节点查看完整规格，点击详情图片放大；可按页面记录修改意见。
- [完整 PRD](产品需求.md)：产品目标、范围、核心规则、验收与待讨论问题。
- [全部页面规格](页面规格.md)：21 个页面、页内区域、弹层和状态的完整说明，以及 7 个规划模块。
- [页面流程图](页面流程图.md)：7 张可编辑 Mermaid 图，覆盖主线、分析、参考图、历史、设置、异常和规划。

## 如何一起修改

直接说“修改 P07 模板卡，把摄影依据默认折叠”或“讨论 Q02 参考图默认开启”，即可精确定位。页面编号在后续版本保持稳定，移除的编号保留废弃记录，不复用。

评审稿中的文字框用于记录意见：保存只写当前浏览器的本机存储，不自动修改仓库、不自动发给助手。点击“整理全部意见”可复制完整文字回到聊天；存储不可用时有提示，刷新前请复制。意见是待讨论内容，不能自动视为已确认需求。

正式修订顺序：确认意见 → 更新需求与页面数据 → 重建评审稿 → 更新变更记录和验证记录。以 [产品需求](产品需求.md) 与 [页面数据](review-data.json) 为内容源；页面规格、流程图和评审稿由脚本生成，避免修改后相互矛盾。

```sh
python3 docs/prd/build-review.py
```

构建只使用 Python 标准库，评审稿不依赖 CDN，不读取私人照片、不调用模型，也不连接应用。图中的“生成完成”等按钮只导航到说明页，不代表真实推理。实际截图、照片代替取景、未采集状态示意分别标记；固定测试数据不代表真实识别结果。图片许可、采集方式和替换方法见 [图片来源](assets/README.md)。

## 状态读法

“已实现”表示在当前源码中有入口；“已有验证”只引用 [验证记录](../验证记录.md) 的具体范围；“待验”不能当通过。“规划”与“本稿建议”没有产品实现承诺。P03–P08、P12 中多项是同一项目工作区的分区或状态，不是新增多个独立路由。
