# 2026-10-03 会话总结：迁移、手机拍摄闭环与端侧参考图

整理日期：2026-10-03。范围：本次长对话从换机接手、Xcode/手机配置，到拍摄项目、双模型分析、真实描边、手机 Qwen 和分级日志。本文保存需求与实现脉络，避免下一次开发依赖聊天历史；具体命令和失败证据仍以 [验证记录](验证记录.md) 为准。后续状态变化更新 [迁移交接](迁移交接.md) 的当前进度，不将本文的日期快照当成永久状态。

## 1. 当前交付结果

已在用户 iPhone 上形成主流程：默认取景 → 拍照或系统相册选图 → 拍摄项目 → 详细照片分析 → 多个推荐模板 → 选择模板继续拍照 → 保存到同一项目并可从历史继续编辑。每个推荐项可以异步生成 AI 参考图，当前由 **此 iPhone 内嵌 Draw Things / Qwen Image Edit 2511** 完成，不依赖 Mac 生成服务。

设置新增本机诊断日志，分级查看模型输入输出、进度和错误，支持筛选与清理。最新代码已签名、安装到手机；本次功能开发最后一次回归为 **77 项测试通过、Swift 构建通过、iOS 真机与 arm64 模拟器构建通过**。本次整理文档没有重新运行这些业务检查，也没有发布到远程仓库、TestFlight 或商店。

当前已实现的是个人手机上的拍摄与推荐闭环。摄影知识驱动的新视角目标轮廓、实时跟拍反馈、通用模型下载器、完整进度交互等仍未完成，不能把这些规划合并成“所有需求已验收”。

## 3. 确认后的产品与数据约定

- 主体不限人物，瓶罐、商品、动物等按实际内容分析，禁止将所有照片默认当作人像。
- 项目是持久任务；照片是原始素材；每次推荐是照片下的批次；模板跟拍生成同项目新照片。换图、重新生成和进入历史不能丢失旧数据。
- 模型给出的粗略框、Vision 的真实观测轮廓、未来设计的新目标轮廓、AI 参考图和实拍原片必须区分。生成图不算实拍、不覆盖原片、不代表精确三维恢复。
- DeepSeek 与 Gemma 是分析来源二选一，当前 Gemma 不提供 edit/gen image。Qwen Edit 是另一个生成任务，和分析模型不共享输出合约。
- 手机 Qwen 不依赖 Mac 服务，不回退云端。未来改图 API 可以实现同一协议，但尚未接入；不能因本机失败而自动上传。
- 选择在线模型并主动生成是单次上传触发；不重新增加已经撤销的许可开关。照片保存本机，重要原片可单独存系统相册；卸载会删除 App 内项目和模型。
- 日志模型正文默认开启是用户明确要求，仅在本机保存且可关闭/清理。它不授权保存密钥、照片编码正文、EXIF 定位，也不授权上传日志。
- 当前个人自用，不购买资源、不升级系统、不自动发布。用户操作 Apple 账号、设备信任和签名账号，项目不复制私人证书或钥匙串。

## 4. 过程中的关键问题与处理

### 4.1 迁移和真机联调

先恢复历史、核对清单、阅读项目约定，再检查环境。Xcode 已能列出 SDK 并不代表平台组件已装好；曾因 `iOS 26.5 is not installed` 不能构建，用户完成下载后才实际通过。设备已信任也不等于启用 Developer Mode；本次设备准备错误通过用户开启开发者模式、重启确认后解除。

工程需要打开 `MelodyCamera.xcodeproj`；把整个目录当作独立 Swift Package 打开可能遇到本地包重复打开/缺 package product。个人 Team 选择后同步 `project.yml`，避免运行脚本重生成工程时丢失签名设置。无线安装、启动、用户确认拍照分别记录，不用某一步成功代表全部硬件已验收。

### 4.2 分析和模板

旧拍后页只有调色，补齐详细分析与返回相机跟拍后，再重组为项目工作区。模型输出先做字段长度、有限数、范围、设备倍率、重复 ID 等校验；无效响应不能进入模板。

Gemma 初次真实输出缺少 `subject`，被业务校验拒绝；增加 LiteRT-LM JSON Schema 约束后复测通过，仍保留业务校验。Vision 提供真实轮廓，语言视觉模型提供观察/拍法，几何代码负责受控摆位；细边缘不依赖模型自己编出点列。

### 4.3 项目、保存与交互修补

从内存会话改为有版本的项目元数据 + 独立原片文件；串行原子保存，单项目损坏隔离，保存失败保留原片并允许重试。跟拍保存来源快照，旧数据没有轮廓时只显示目标框，不补造历史。

全屏查看曾出现空白，改为通过 `fullScreenCover(item:)` 传递不可变预览数据；倍率切换曾清空模板，修复为只更新相机倍率。画廊读取不触发每页重新分析，退出定位最后查看的照片。原片/副本保存与模板显示状态分离。

### 4.4 参考图路线纠正

早期先做了 Mac CLI 和局域网作业服务，包含真实生成、开发容器导图、手机网络超时及后续无线端到端复验。**容器导图当时只验证展示/恢复，不能证明网络调用或手机端侧生成**。超时根因未确定，不能写成用户 Wi-Fi 或权限错误。

用户随后明确 Mac 代算没有产品意义。停止 Mac 服务、撤销 App 默认 Mac 配置和相关入口，保留独立作业/异步卡片/供应商协议，改用手机内嵌官方引擎。旧服务脚本和 ADR 004 是历史实验，不是下一位接手者要恢复的部署步骤。

提示词实验中，模型曾把“摄影者移动”等机位说明画成新增人物和线缆。增加“动作发生在画面外，禁止新增物体”的约束后改善，但单张成功不代表主体一致性或角度可靠性普遍通过。

### 4.5 手机内存与模型资产

高级 Pipeline 首次在手机触发 `mpmemmap / aligned_ptr == bufptr` 断言。尝试扩展虚拟地址 entitlement 被 Personal Team 拒绝签名，随后撤销；这一失败不足以证明最初断言的全部根因，也不意味着个人开发能占用全部物理内存。

最终从固定官方 SDK 链接 `LocalImageGenerator`，本地 workspace 设置 `JITWeightsLoading.alwaysFully`，权重缓存为 0，按需加载，不做远程模型目录解析。Gemma 和 Qwen 共用串行模型槽，显式管理占用，避免 actor 在 await 期间重入导致同时加载。

Qwen 整套约 28 GB、Gemma 约 2.59 GB，均独立放入应用支持目录、排除备份，不随每次 App 编译重新打包。SDK 首次运行会拆分 VAE 元数据/tensor，完整性检查已兼容原始版和优化版；缺失/截断仍拒绝。普通用户下载器、断点续传与空间管理未完成。512 输出降低运算和激活成本，不会消除权重磁盘需求。

### 4.6 日志设计

系统侧用 Apple Logger 分类分级；App 自己保存有界日志以支持可靠查看和清理。模型正文只入本机文件，系统日志只收简短事件。在线请求只提取允许的文本和图片尺寸，不序列化整个请求/headers；未知 NSError 只记录受控类别和错误码。日志使用后台串行队列排序，避免清理后旧待写事件复活，原子写入、文件保护、排除备份。

使用调用 ID 关联输入、返回、校验与失败；Qwen 沿用任务 ID 查看现有生成图，不另存图片。SwiftUI 只在快照变化时刷新，避免每两秒无条件更新打扰菜单。App 清理自己的记录，不声称清除 iOS 系统诊断或捕获所有崩溃。

## 6. 接手顺序和下一步

1. 按 AGENTS 阅读入口、本文及当前交接；确认代码状态和已有模型，不覆盖未提交工作、不卸载手机 App。
2. 先补当前手机体验验收：连续拍摄、原片/副本相册回看、全屏手势、拒绝权限/后台恢复，增加瓶罐/人物/复杂背景样本。
3. 检查 Qwen 长时间任务的取消、后台、热量、内存和相机并发压力；其余三种分辨率、飞行模式单列验收，不重复从“手机到底能不能出图”开始。
4. 为模型资产做可用空间、断点下载、校验、取消和版本管理；保持免费签名可用，后续若改变账号或分发范围再单独决定。
