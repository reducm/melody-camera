# 根据原片与拍摄模板生成参考图

> 2026-10-03 方向纠正：手机通过 Mac 生成并非用户目标，现已撤销这条默认产品路径。本文中的 Mac 部署/出图数据仅为历史实验；当前决策以 [ADR 005：iPhone 端侧参考图](adr/005-iPhone端侧参考图.md) 为准。

调研日期：2026-10-03。状态：已完成此 iPhone 内 Draw Things / Qwen Edit 异步接入与 512 方图真机生成；下面各路线保留原调研背景，当前使用 ADR 005，模型下载和实测进展见 [验证记录](验证记录.md)。本机硬件实测为 Apple M1、16 GiB 统一内存；手机为 iPhone 17 Pro Max。下文外部性能数据不能当成本项目测试结果。

## 结论与候选

这个方向成立：输入原图、推荐文案和目标机位，输出低分辨率的“下一张照片可能怎样构图”的参考稿。应选具有原图条件输入的编辑模型；只用文生图容易丢失当前主体。图像编辑仍会补造不可见表面，不能把图像当作真实重建，也不能让生成图覆盖原片。

| 候选 | 已核实的能力 | 本项目判断 |
|---|---|---|
| Qwen-Image-Edit-2511 | 官方图生图模型，20B；提供多图输入与新视点展示，模型卡标注 Apache-2.0 | 作为角度编辑质量基线；未经量化与运行时优化，不直接放入 iOS 工程。来源：[官方模型卡](https://huggingface.co/Qwen/Qwen-Image-Edit-2511) |
| fal Multiple-Angles LoRA | 基于 2511，提供方位/俯仰/距离提示格式；作者列出 96 种组合 | 比自由文案更适合将机位枚举映射为约束；属于生成控制，不保证真实相机精度。来源：[作者模型卡](https://huggingface.co/fal/Qwen-Image-Edit-2511-Multiple-Angles-LoRA) |
| LightX2V 2511 Lightning | 提供 4 步蒸馏 LoRA 和融合量化模型 | 可测“低清快速草图”路线；须使用匹配的底模/LoRA/采样参数，不能套在其他版本上。来源：[作者模型卡](https://huggingface.co/lightx2v/Qwen-Image-Edit-2511-Lightning) |
| Qwen-Image-2.1 | 官方统一生成/编辑，视觉生成部分 7B，支持多参考图，许可证为 Qwen Research License | 纳入新版本对照；7B 不代表整个管线只有 7B，也不能继承 2511 的 LoRA 或许可假设。来源：[官方模型卡](https://huggingface.co/Qwen/Qwen-Image-2.1) |

## 三条本地运行路线

### A. iPhone 端侧：值得验证，不直接承诺秒出

Draw Things 已公开支持 Qwen 的 iPhone 本地推理，并解释了 FP16 数值缩放、VAE 优化、预计算条件降低常驻权重的实现。它的发布记录同时列出 Edit 2511 和 2.1 支持。因此，**不能仅以参数量断言 iPhone 跑不了**。但这证明的是经过专项优化的产品，不是任意 Python 管线都能嵌入 Swift App。[端侧工程说明](https://engineering.drawthings.ai/p/optimizing-qwen-image-for-edge-devices)、[版本记录](https://drawthings.ai/downloads/)。

Draw Things 作者报告：iPhone 17 Pro 上 Qwen Image + Lightning、768×768、2 步的端到端生成约 45 秒以上。这是厂商的特定文生图配置，**不是本机实测，也不是 Edit 2511 多参考图/角度 LoRA 的速度**。本项目不能承诺相同耗时。[原始性能报告](https://releases.drawthings.ai/p/iphone-17-pro-doubles-ai-performance)。

建议先用独立原型确认 512 级别原图编辑的质量和内存，再决定移植。手机推理时需要卸载 Gemma、停止相机占用、限制并发为 1，并验证取消、切后台、热状态及内存压力；Swift 适配层与 Core 协议隔离。Draw Things 社区仓库有公开推理代码和 macOS SwiftPM CLI，但标注 GPL-v3；复用范围、第三方依赖和将来的分发方式需明确后再选运行时，不能当成无约束的商用 SDK。[作者仓库](https://github.com/drawthingsai/draw-things-community)。

### B. 这台 Mac 本地：优先受控原型，关注 M1 / 16 GiB

MFLUX 有 MLX 原生 Qwen 图像编辑实现及 LoRA 支持。旧版 Qwen 文档提示低比特量化可能损伤质量；变更机位时尤其要核对主体形状、标签与文字。[MFLUX Qwen 文档](https://github.com/mflux-community/mflux/blob/main/src/mflux/models/qwen/README.md)。

2.1 的普通生成路径和 reference-edit 路径的量化策略不同，不能混读：前者文档描述未量化常驻文本编码器及约 46 GB 峰值；后者支持对可用 transformer/text-vision 层量化，提供 512 reference budget、低内存和 VAE 分块选项，但没有给出本机 16 GiB 可稳定运行的保证。后者首次下载原始权重仍约 33.1 GB。参考图实验应使用 **reference-edit**，并钉住运行时 commit 和模型 revision。[普通路径](https://github.com/mflux-community/mflux/blob/main/src/mflux/models/qwen21/README.md)、[参考编辑路径](https://github.com/mflux-community/mflux/blob/main/src/mflux/models/qwen21/reference/README.md)。

建议先比较 Draw Things 的量化编辑路径与 MFLUX reference-edit；不要一开始下载全精度全量 2511 并与 Xcode/Gemma 同时常驻。低分辨率减少激活和图像 token 计算，不能消除底模、文本/视觉编码器和 VAE 的权重成本。早期 Mac 实验选择独立官方 Draw Things CLI 与 Qwen Edit 2511 量化权重；当前产品已改成手机内嵌引擎，操作说明见 [本地参考图](DrawThings本地参考图.md)。

### C. iPhone 调用同局域网 Mac：已撤销的历史过渡实验

可在 Mac 上做独立作业服务，iPhone 点击“生成参考图”后传递去定位的缩略图与结构化模板。必须在 UI 标为“Mac 本地生成”，区别于“此 iPhone 本机生成”；这仍是离开手机的数据传输，不能因为同 Wi-Fi 就自动上传。显示目标主机、确认配对、限定接收端和取消机制；不能默认开公网端口，也不将密钥或私人原图写日志。历史服务与手机异步接口曾实现并完成无线复验，随后被手机内嵌路线替代；当前不应恢复运行。

## 建议的首个实验

1. 公共样图/用户主动选择的测试图：不透明瓶罐、反光罐、人物、复杂背景各若干张；每张至少比较保持正面、左前 45°、低机位三种建议。
2. 统一输入：原图缩略图 + 主体选择 + 结构化机位 + 主体大小/位置 + 推荐理由。输出先测试 384×512 或 512×512；保持画幅，按运行时要求对齐尺寸。低清只是参考，不能跳过正确性检查。
3. 2511 原生编辑作为质量基线；匹配的 4 步 Lightning 和角度 LoRA 分别启用，再测试组合。2.1 单独配置，不能拿旧 LoRA 直接混用。只有兼容蒸馏权重才用低步数，普通模型少跑几步不等于可靠加速。
4. 记录冷启动/热启动耗时、真实推理步数、峰值内存、失败/取消、热状态；人工核对主体身份、轮廓、角度是否遵循、背景可实现性。不要写未经测量的“几秒出图”或综合评分。
5. 未通过时继续保留已生成的文字和受控模板，不阻塞拍摄，不静默调用云服务。以用户是否更容易照着拍为目标，不以参考图画质最高为目标。

当前产品路径：先显示文字与粗轮廓；参考图开启时，各推荐项自动按顺序生成，也可为已有模板手动补图。未来再从参考图提取**设计轮廓**供跟拍，这一步尚未实现。参考图、设计轮廓、实拍原片使用不同类型与标签。详细数据和任务架构见 [推荐引擎架构](推荐引擎架构.md)。
