# ADR 006：本机分级日志与模型调用详情

日期：2026-10-03。状态：已实现，验收范围见验证记录。

## 决策与理由

用户需要在设置中查看、清理日志，并特别要求看见模型输入输出。采用 Apple `Logger` 的 subsystem/category/level 记录系统事件，同时维护 App 自己的有界本机日志文件。系统日志的保留由 iOS 管理，`OSLogStore` 提供读取能力，没有供 App 清空系统日志的公开 API，所以不能用它冒充“可清理的本机日志”。不引入外部日志平台或第三方埋点 SDK。

- 入口：设置 → 诊断日志。Debug / Info / Warning / Error，按级别和功能筛选，最新在前，前台每 2 秒更新，也可下拉刷新。
- 功能类别：应用、相机、照片分析、参考图、存储、模型安装。详情展示同次调用的输入、输出和错误，使用随机 UUID 关联。
- 默认记录模型正文，这是用户本轮明确要求。可在页面关闭“记录模型输入与输出”，只影响之后提交的正文；已有内容通过清理删除。
- 保留最近 7 天、最多 500 条、总文件最多 2 MiB；单条正文最多 32 KiB，截断明确标记。清理针对所有类别与级别，并有确认提示；正在运行的任务仍可能产生新的记录。

## 边界与隐私

`DiagnosticLog` 位于 App 层，Foundation + OSLog，不污染 MelodyCore。串行后台队列将写入、过期轮转、读取和清理排序；文件原子替换，避免已有待写记录在清理后复活。位置是 `Application Support/Diagnostics/events.json`，排除备份，iOS 使用 `completeUntilFirstUserAuthentication` 文件保护。读写失败在日志页显示，不能将内存记录冒充已落盘记录。损坏文件不会导致启动崩溃。

模型文本仅进入 App 管理的本机文件；系统 Logger 只收到短事件标题且使用 private 隐私级别。不开启上传、外部导出或自动报错服务。没有实现 crash handler；崩溃诊断仍由系统管理，本机日志只提供已经完成写入的事件。

在线适配器装饰原有 transport，仅抽取 `messages` 的文字、模型 ID、token 上限和图片尺寸/字节数。响应只抽取 `choices.message.content` 或 error 的 message/type/code；超过 256 KB 或无法解析时不记录原始响应。永远不序列化整个 URLRequest、headers、HTTP body 或 NSError.userInfo。已知当前调用密钥、Bearer、sk- 凭据、URL、data URI 和长编码串再次过滤；这只是纵深防护，允许字段的提取才是边界。未知底层错误记录受控类别和错误码，不记录路径、网络地址。

不记录图像正文、原片、EXIF、位置元数据、钥匙串或证书。模型正文可能描述照片中的私人内容，因此页面明确说明仅在本机保存，可关闭和清理。模型文字始终以纯 Text 显示，不执行 Markdown、链接、代码或远程内容。

## 各模型记录范围

| 模型/流程 | 输入 | 输出 |
|---|---|---|
| 在线视觉，包括 DeepSeek | 实际请求中的文字、模型、token 上限、图片尺寸/大小 | 实际返回文字（校验前）、HTTP 状态、耗时；无效响应和网络错误 |
| 本机 Gemma | 实际摄影提示词、图片尺寸/大小、固定推理参数 | 实际返回文字（结构校验前）、校验结果和耗时 |
| 本机 Qwen / Draw Things | 传入的摄影提示词、图片尺寸/大小、分辨率；实际 seed、采样器、步数、CFG 等 | 状态/采样进度、输出尺寸/大小、含排队总耗时；详情可读取原参考图并放大 |
| Apple Vision | 轮廓提取完成/失败 | 轮廓数量，不保存蒙版数组或图像 |

Qwen 日志通过调用 ID 读取已有参考图，不另存图片；清理日志不删除照片或推荐结果。模型调用编号只用于日志关联，不是账号或设备标识。

## 验证与后续

### 2026-10-04：读取最近错误与响应回放

已连接并信任的开发用 iPhone 可以通过 Xcode `devicectl` 读取 App 沙盒中的 `Library/Application Support/Diagnostics/events.json`；无需用户截图或重新生成。文件数组按写入顺序保存，取最后一个 `Error`，再按它的 `operationID` 关联同次输入、HTTP 输出和校验结果。只复制日志文件到被 Git 忽略的本机 `artifacts/`，不复制照片、模型或钥匙串，真实模型正文不进入知识库和测试夹具。

HTTP 200 仅证明请求有响应；模型正文的 JSON 解码、字段/坐标/倍率校验与知识推荐是后续阶段。此次排错发现模型将 `scene` 写在根对象外：提示词改为一个包含全部字段的 JSON 示例，在线适配器只兼容“完整报告提前闭合后追加唯一 scene”的确定格式。兼容后仍完整校验；成功会用相同调用 ID 记录 Warning「已兼容模型 JSON 的 scene 外置格式」，不重传照片或自动重试。其他损坏/歧义内容拒绝，并提示照片分析 JSON 问题，避免误导用户更换视觉接口。

Debug 参数 `--melody-check-last-analysis-response` 在手机或模拟器内回放最近一次分析错误所关联的 HTTP 200 正文，执行同一解析器与知识规划器；输出 `Documents/analysis-response-check.json`，只有通过状态、是否兼容、scene 是否存在、模板数量和来源错误 ID。不会显示模型正文、修改项目、读取照片、启动相机或调用在线/本地模型。该回放采用 0.5/1/2 倍率和默认构图上下文，只验证已记录响应的适配及规划，不替代原片轮廓或新的端到端模型验收；正文关闭、日志轮转或清理后可能无法回放。

单元覆盖持久化/恢复、清理顺序、并发写入、级别、数量/字节/时间限制、脱敏/截断、正文开关、损坏与写入失败、在线失败响应和网络异常。iOS 模拟器与真机结果单列在验证记录。

后续可按实际排错需要加入 MetricKit 汇总和用户主动导出；当前没有后台上传、自动收集第三方 SDK stdout、性能评分或虚构百分比。日志容量是总量上限，同次调用的很早事件可能因轮转被移除。
