# ADR 003：以拍摄项目统一取景、推荐、跟拍与编辑

日期：2026-10-03。状态：已采用。

## 问题与决定

原界面同时出现实景入口、演示、构图灵感、快门和独立拍后弹窗，分析结果又只存在内存，用户不清楚下一步。改为一个长期拍摄项目承载整个过程：

`拍摄项目 → 多张照片 → 每张照片的多轮推荐 → 选模板跟拍 → 同项目新照片`

启动默认实景取景，中央快门只负责拍照；权限/硬件不可用时显示明确失败与选图/重试，不把演示当相机。首次拍摄或选图创建项目；用户点击“新建项目”才结束当前上下文。历史入口是已有项目的继续编辑入口，启动不强制打开上次项目。

## 界面

- 取景页：顶栏历史/项目名/新建/设置；中间3:4全画幅取景、目标叠加；下方倍率、相册、快门、当前项目。删去顶部大“开启实景”按钮与无照片的模型推荐堆叠。
- 项目页：照片时间线、当前照片、推荐与模板/编辑照片两个工作区。底部固定“重新拍摄、选照片、生成推荐/再生成一轮”。详细分析折叠，模板是主要行动。
- 推荐按照片分组，批次可切换；失败/取消不会删除已有报告。换图保留旧照片与推荐。选模板后回到同项目取景，跟拍新照片记录父照片/批次/模板引用。
- 历史展示封面、项目名、照片和推荐数、时间；打开恢复当前照片、选中推荐与调色配方。仅本机存储，卸载会删除；不自动云同步。

## 数据与持久化

Core 的 `ShootingProject / ProjectPhoto / RecommendationBatch / CaptureReference` 不依赖SwiftUI或相机。`ProjectLibrary` actor 只做本地文件读写；UUID生成文件路径，不接收模型提供的路径。

项目文件使用schemaVersion=1，拒绝未知版本；本轮早期无版本文件按v1兼容读取。原片独立保存且不覆盖，项目JSON原子写入；App层串行保存快照，照片/批次切换不和旧任务争写。报告从磁盘恢复时仍执行业务校验。历史损坏按单个项目隔离，不把整个列表当空库重置。保存失败保留当前原片、给出重试状态，新建项目按钮暂不可用。应用支持目录排除备份；默认不自动向系统相册重复写入。

没有沿用内存 `session` 作为持久ID，也不把一次模型请求当整个项目。旧版未持久化的照片无法从已终止进程恢复；本版从新增照片开始保存。

## 验证重点

新增照片不丢旧片、重复生成不覆盖批次、失败重试保留上轮、模板跟拍关联正确、重启后原片字节与配方一致、磁盘失败可见、单项目损坏隔离。默认相机启动、权限拒绝、系统相册、历史打开与跟拍需单独做iOS验证。

## 2026-10-03：项目详情交互补充

按用户最新要求取消独立上传许可开关。在线/本机选择决定执行端，点击生成推荐是单次请求的明确触发；导入、拍摄、恢复项目不自动分析。此规则替代早期文档中的会话上传开关。

项目自动名称每轮跟随非空主体名，用户手动改名后保留自定义名称。新增可选持久字段保持旧项目可读。跟拍来源新增可选轮廓快照，原方案仍从原推荐批次获取；没有轮廓的历史只提供目标框，不重新猜测原模板。

全屏看图用 UIKit 原生滚动缩放组件承载 UIImageView 和受控描边，避开 Quick Look 临时文件生命周期并允许同步缩放模板。主照片区的保存菜单分别保存原片和调色副本；模板显示状态不影响导出像素。
