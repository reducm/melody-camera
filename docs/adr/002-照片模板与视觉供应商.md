# ADR 002：真实描边模板、视觉供应商与本机 Gemma

日期：2026-10-03。状态：已采用，真机效果以验证记录为准。

## 需求

对人物、瓶罐和其他物体的照片输出详细观察、主体轮廓、目标摆位以及机位建议。在线和本机推理可替换，默认不上传图片。

## 决策

- `PhotoAnalyzing` 是照片分析统一协议。`OnlinePhotoAnalyst` 使用受限 Chat Completions 兼容接口；`GemmaPhotoAnalyst` 在 App 适配层依赖 Google 官方 LiteRT-LM 0.16.0。两个路径共享提示词与 `PhotoAnalysisCodec`，检查结构、文本长度、重复 ID、倍率和坐标。视图不创建网络请求。
- DeepSeek 官方 `deepseek-flash` 已通过公开图片实际图像输入与完整业务 JSON 合约测试；仅对确切官方域名/模型启用 non-thinking 和 JSON 参数。不是对所有品牌/兼容服务的能力背书。
- 主体像素分割使用系统 `VNGenerateForegroundInstanceMaskRequest`，从实例 mask 提取并简化轮廓。可选择多个主体。失败只显示目标范围，不用人物图形冒充真实描边。模型给出的 detectedSubject 是粗略范围，不是像素 mask。
- 轮廓模板保留原物体比例，缩放、平移到建议范围并叠加在相机取景中。不同机位是明确的拍摄建议；单张图不够恢复隐藏表面，本版不声称得到新视角实拍或 3D 重建。
- iOS 照片导入使用 PhotosPicker；原始字节保留，上传另生成去定位缩略图，编辑保存副本。
- Gemma 固定 `gemma-4-E2B-it.litertlm`，来源 litert-community/gemma-4-E2B-it-litert-lm、修订 6e5c4f1，大小 2,588,147,712 字节，SHA-256 `181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c`。模型独立安装于应用支持目录、排除备份，导入时分块校验，不嵌入 Git 或主应用包。GPU 文本 + CPU vision，关闭 thinking，取消调用 SDK cancel。没有权重时明确提示，绝不假装离线规则是 Gemma。
- API Key 存钥匙串。Debug 可消费由开发电脑经配对设备容器传入的一次性配置，写入钥匙串后立即删除；Release 不包含此入口。预配置不触发分析；按后续 ADR 003 取消上传开关，选择在线并主动生成才发送照片。
- LiteRTLM 0.16.0 官方预编译框架只有 arm64 真机/模拟器切片，因此工程明确排除 Intel 模拟器架构；支持当前 Apple Silicon 开发电脑。

## 备选方案

Swift 生态存在 [swift-ai-sdk](https://github.com/teunlao/swift-ai-sdk)（多 provider、generateText/结构化输出）以及 [AnyLanguageModel](https://github.com/huggingface/AnyLanguageModel)（云端与本地统一接口）。它们并非 Apple 官方或 Vercel 官方 Swift SDK。当前只有一个云端协议与一个本机运行时，使用小接口避免引入大批无关 provider 和额外兼容风险；将来扩展服务商可在适配器内部接 SDK，不改 UI/业务结构。

Meta [EdgeTAM 官方 Core ML 转换脚本](https://github.com/facebookresearch/EdgeTAM/blob/main/tools/README.md) 提供 image encoder、prompt encoder、mask decoder，可用于 iOS。原 SAM/部分 SAM 2 导出有算子、内存和交互提示依赖，不能当成直接拖入即用的单一 Swift 模块。本轮先使用系统分割，未集成 Meta 权重；只有在复杂背景/细边缘样本证明系统方案不足时，再引入并用同一轮廓接口替换。
