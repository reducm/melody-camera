## 实现入口与修复

知识引擎为 `PhotographyKnowledge`、`RecommendationEngine`、`CompositionDesign`、`ReferenceDesign`；完整说明与来源见 [实现](知识推荐引擎实现.md)、[调研](摄影知识与推荐模型调研.md)、[ADR 007](adr/007-知识驱动摄影推荐.md)。

本轮发现并修复：选用生成图的新轮廓后，原 `ShotPlan.instruction` 与 `design.steps` 没有更新，会出现轮廓在右、文字仍指向左，或错误沿用旧主体占比的靠近/后退提示。先加入 `adoptedReferenceGuidanceUsesNewTargetInsteadOfOldPlacement`，实测出现 3 个失败断言；修复后按新轮廓中心生成方向，重新对照大小，不沿用旧距离判断。参考图卡片同时显示采用后的跟拍文案；跟拍历史保存修正后的不可变快照。

同时清理 Mac 旧导入入口“需要单独开启上传”的过期文字，统一为选择在线模型并主动生成才上传；没有恢复独立上传许可开关。

新增 `PublicPhotoRegression`、显式环境变量测试入口、`--melody-check-public-photos` Debug 模拟器入口、公开样本清单与两份脚本。固定输入、快门替身与真实像素处理分开标注；真实集成入口缺参数时改为显式 skipped，避免空返回被误读为真实服务通过。详情见 [公开照片回归](公开照片回归.md)。

## 真实验证结果

- Swift Testing：89 个测试定义，两个单图/真实在线集成入口因没有参数而明确跳过，其余 87 个执行通过；其中知识矩阵包含 28 个参数场景。XCTest 8 个全部通过。公开多照片集成入口本轮已显式开启。
- `swift build`、iOS arm64 Simulator 构建、iPhone arm64 无签名构建均通过。没有安装或启动手机应用。
- 7 张公开照片各跑四种风格、四种调色，导入、导出、历史、损坏输入、替身倍率/跟拍以及本机生图不可用降级全部通过。Mac 上 6 张提取到轮廓，山地风景无可靠主体；模拟器上 7 张均未提取到轮廓，走明确降级。不能把降级检查通过写成分割成功。
- 模拟器实际调用系统相册保存原片/副本，允许权限时完成保存；拒绝权限时明确报错并保持原片和项目。系统权限由 simctl 预置，未点测授权弹窗。
- 模拟器独立日志目录的持久化、脱敏、恢复与清理均通过，未点测清理确认框。
- 工程通过 XcodeGen 同步，两个 plist 检查通过；脚本语法、Python 编译检查和 diff 空白检查通过。

原始结果位于忽略的 `artifacts/2026-10-04/simulator-regression/`。它们可清理，长期证据以本文和 [验证记录](验证记录.md) 为准，不依赖某台电脑绝对路径。

## 关键失败与处理

1. Mac 已锁屏，Computer Use 明确无法解锁，因此没有继续要求离开键盘的用户操作。改做程序内模拟器回归；没有把这些检查或旧截图冒充 UI 点击。
2. 第一次 generic 模拟器构建启动了依赖的额外 x86_64 编译，主动中断后固定 `ARCHS=arm64 ONLY_ACTIVE_ARCH=YES`。项目 LiteRT 本身只支持 arm64 模拟器。
3. 添加 Debug 回归文件后，旧工程缺文件引用导致一次编译失败；从 project.yml 重生成工程后通过，未手改个人 Team 或 Bundle ID。
4. 后续 xcodebuild 卡在 `IDEWorkspace → NSFileCoordinator` 文件协调等待，未进入编译。保留采样栈并中断自己的命令，将源码、工程和配置复制到忽略的隔离构建目录继续；最终 Simulator 和 Device 构建均通过，39 个源码/工程/Info 文件与工作区 SHA-256 一致。没有强制退出用户 Xcode 或删除缓存。
