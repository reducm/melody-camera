# Apple Vision、DeepSeek 与 Gemma 的职责

更新：2026-10-03。能力来源已核对 [Apple Vision 官方文档](https://developer.apple.com/documentation/vision)。系统能力存在，不等于本项目已经接入；新接口的系统最低版本与运行成本要逐项核实。

## 当前代码真正做了什么

| 组件 | 输入与输出 | 当前用途 |
|---|---|---|
| Apple Vision | 原片→前景实例mask→轮廓点列 | 本机提取真实主体边缘，供原图核对和模板叠加，不上传 |
| DeepSeek Flash | 压缩照片+业务提示→结构化照片报告 | 云端看图，输出主体名称、光线/构图/背景/姿态/成像观察、下一步和1–3个拍摄建议；选择在线模型并主动生成才调用，不设额外上传开关 |
| Gemma 4 E2B / LiteRT-LM | 压缩照片+业务提示→同样的报告 | 在iPhone本机推理，不依赖上传/Key；用约束解码保证字段，仍需业务校验 |
| Draw Things / Qwen Image Edit 2511 | 原照片 + 推荐文案/机位 → AI 生成参考图 | 在此 iPhone 内异步生成，已实测 512 方图；不覆盖原片，不保证几何精确，也未从生成图提取设计轮廓 |
| Core 几何与校验 | 目标框、受控机位、实际轮廓→可渲染模板 | 等比移动真实轮廓、画机位图；并非模型直接绘图，也不是新视角重建 |

DeepSeek 与 Gemma 是可选择的分析来源，没有默认同时调用或互相验证。它们当前没有检索摄影知识库、没有生成新角度的照片/轮廓、没有完成实时跟拍对齐。细轮廓不依靠它们输出的粗略框。Gemma端侧能力受模型规模影响，两者都可能给出错误观察与动作，结构合法不等于建议正确。

## Vision 值得接入的能力

| 系统能力 | 在本项目中的潜在收益 | 当前状态与边界 |
|---|---|---|
| 人体/手部关键点、3D人体姿态 | 人像站姿、手部动作、目标骨架对齐 | 未接入；3D人体姿态不是任意商品的3D重建 |
| 人脸位置与特征点 | 检查脸部遮挡、头部位置，辅助连拍选择 | 未接入；不用于身份识别或外貌评分 |
| 目标跟踪、光流、图像配准 | 模板跟拍时持续追踪同一主体，减少每帧重新分割 | 未接入；跟踪可能漂移，需要丢失重检和稳定性规则 |
| 人脸拍摄质量、图像美学指标 | 连拍候选的技术质量/模型偏好辅助信号 | 未接入；不是客观好看分，也不能替代用户选择 |
| 注意力/主体显著性 | 提示主要视觉焦点、背景抢眼位置 | 未接入；显著区域不保证就是用户想拍的主体 |
| OCR、条码、矩形/文档检测 | 商品文字、说明牌或文档类场景理解 | 未接入；按需运行，不应自动收集所有可见文字 |
| 前景实例分割、轮廓 | 主体与背景分离、实际边缘 | 已接入静态照片；透明、细小、反光边缘仍需实测 |

建议顺序：先完成项目体验，再做“人体关键点/目标跟踪 + 模板对齐反馈”，随后连拍选片。新的目标轮廓由 [推荐引擎](推荐引擎架构.md) 设计，Vision提供观测几何，不应让分割模型承担摄影知识与目标创作。
