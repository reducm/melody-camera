# 知识推荐引擎 v1 实现与验收

调研开始：2026-10-03；开发交接：2026-10-04。分支：`codex/knowledge-guided-recommendations`。状态：**Swift 测试、Mac 构建、iOS 模拟器构建和公开照片流程回归已执行；锁屏期间未做 UI 点击，新模型合约及真机摄影效果待验收**。选型见 [ADR 007](adr/007-知识驱动摄影推荐.md)，资料见 [调研](摄影知识与推荐模型调研.md)。

## 使用过程

拍照或导入 → 选择实际主体与拍摄风格 → 主动生成推荐 → 查看摄影依据、步骤、条件与目标模板 → 可立即按模板拍摄。参考图在原有手机 Qwen 分支异步生成。

参考图若提取到完整主体轮廓，卡片出现“核对并选择参考图轮廓”。用户在 3:4 裁切预览中选择主体，核对身份/数量/细节、角度/构图和现场可执行性后，才选用新的设计描边。可以恢复知识构图模板。审核不是自动视觉认证，也不会改变已开启取景器中的模板；再次点击跟拍时才采用新选择。

## 模块与数据

| 文件/类型 | 职责 |
|---|---|
| `PhotographyKnowledge.swift` | 4 种风格、结构化观察、10 张带来源的知识卡、分析上下文 |
| `RecommendationEngine.swift` | 技巧适用性过滤、风格排序、125 个参数候选搜索、几何目标、动作生成与校验 |
| `DesignedTemplate.swift` | 设计来源、简化轮廓、3:4 裁切映射、参考图审核与方案采用 |
| `PhotoAnalysis` / Schema / Prompt | 在线与 Gemma 都返回受控 scene；保留旧报告兼容 |
| `ReferenceGenerationController` | 生成后分割、按作业保存审核状态、取消/重试隔离 |
| `StudioModel` | 将观察转换为知识方案、固定照片/主体/风格快照、应用方案并保存跟拍快照 |
| SwiftUI 现有视图 | 风格选择、依据与步骤、设计来源、参考图核对、水平参考线 |

Core 不依赖 SwiftUI、Vision、AVFoundation 或模型 SDK。实际分割仍在 MelodyImaging；App 负责模型、持久化和相机。没有新增第三方依赖、数据库服务或网络调用次数。

`SceneEvidence` 包括主体类别、类别形状、主体数量、朝向、背景复杂度、光线、原机位、桌面、地平线、最多 8 个背景干扰框。它是模型观察，不是测量或置信度；所有未知属性明确用 unknown、地平线用 -1。字段完整时校验数量、有限数和范围；旧响应完全没有 scene 时退化为一个明确标注的保守目标框。

为结构化观察预留上下文，Gemma 的 `maxNumTokens` 从 4096 调整到 8192，输出上限仍为 2500；提示与约束 schema 只要求一个初步方案，本机再计算最终 1–3 个方案。此参数变更的实际内存、耗时和完整 JSON 输出仍待真机验证，不能沿用旧版 Gemma 单次耗时记录。

`CompositionDesign` 保存引擎版本、知识版本、技巧 ID、风格、来源类型、受控轮廓、动作步骤、条件、可选地平线与生成作业 ID。模型不得提供本机审核和设计元数据；provider 解码会剥离这些字段，知识规划器生成自己的元数据。

## 知识检索与候选算法

4 种风格为自然纪实、环境叙事、简洁留白、主体质感。10 张卡为视线空间、错开中心、简洁留白、环境关系、减少干扰、居中、桌面俯拍、较高机位体积、多人完整、地平线。

先过滤硬条件：人物/动物且左右朝向明确才启用视线空间；确认桌面、平面食物/物件才启用正上方；桌面上的筒状/盒状商品才启用类别几何新机位；多人不借用单实例描边；低光优先接近 1× 的可用倍率。没有设备可用倍率即拒绝，不自动制造 2× 能力。

适用卡片按风格匹配和场景相关性排序，权重是工程配置。每张卡定义偏好的主体高度和中心关系，以 5 个高度、5 个水平偏移、5 个垂直偏移枚举 125 个目标候选。宽度从真实分割或粗框的物理长宽比推导，边缘保留 6% 范围，宽高统一缩放以避免拉伸。不是只能把描边放到九个格子。

内部代价由中心偏离、尺寸偏离、视线空间违背、重取景后可见背景干扰面积和轻微移动惩罚组成。同平面重取景假设下，用主体框之间的变换估计背景干扰；新视角不沿用此估计。此方法不恢复深度，不能保证相机移动后的真实遮挡关系。代价不显示成审美分数，也不称为模型置信度。

不同卡片的候选按角度、中心和尺寸差异去重，最多保留 3 个。条件不足可以只返回 1 个，不用改标题凑数量。没有跨轮保证去重，用户反复生成相同观察可能得到相同规则方案。

动作与同一套几何绑定：先设置机位/检查背景，选择可用倍率并说明目标位置，再调整距离。大小比较考虑当前倍率到推荐倍率的平方关系，以及原图转为相机 3:4 的面积差异；不虚构米数、步数或相机标定。新角度方案不根据旧 2D 面积给出距离推断。

## 三类初始模板与生成图轮廓

- `observedPlacement`：同视角方案，原轮廓等比摆位；仍清楚标注来源。
- `geometricDesign`：针对筒体、盒体与平面物件生成受控体块/俯视示意。顶面与侧面结构确实不同于原片描边，属于类别设计；不会恢复瓶背文字、精确比例或人体姿态。
- `framingOnly`：信息不足、多人或无可靠轮廓时，仅显示目标范围，避免假人体/假分割。
- `generatedReference`：从实际 Qwen 生成图分割、用户明确核对后采用的新轮廓。

保存的设计轮廓最多 2 条路径、每条 48 点，在 Core 重新校验；使用原片描边时先简化，避免历史 JSON 体积失控。模板报告继续走 32 KiB 的现有上限，不执行模型 SVG/HTML 或代码。

若较长的观察文字与多条描边共同超过报告上限，按排序移除末尾候选，优先保留首选方案；不截断原始观察字段，也不静默放宽数据合约。

参考图的目标参数统一以竖向 3:4 表达。全局生成分辨率仍保留原有四项，提示词要求不同输出画幅将构图保留在中央 3:4 区域。**文字不是硬约束**，因此完成后还需实际像素分割与人工核对。

设参考图宽高比为 a、目标 c=0.75。中央裁切窗口为 `w=min(1,c/a)`、`h=min(1,a/c)`，原点为 `((1-w)/2,(1-h)/2)`；映射轮廓点时减原点再分别除以 w/h。只有主体包围框完整包含于此窗口才保留。UI 使用同一中央填满裁切，坐标与预览一致。未提取到轮廓、裁切切边或分割失败时仍保存参考图，原知识模板可继续用。

## 持久化与时序

- 每次分析固定项目 ID、照片 ID、原片缩略图、主体范围和风格；等待模型后重新核对来源，取消或切换不能回写到另一张照片。
- `ReferenceDesign` 绑定作业 ID；未核对前没有可应用轮廓。必须勾选三项并选中合法候选才可批准。重新生成产生新作业，旧作业不能通过审核接口冒充最新结果。
- `ReferenceJob` 持久保存候选与审核；恢复时校验作业 ID、路径和批准状态。提取失败不影响成图，取消后不写完成状态。
- `CaptureReference.planSnapshot` 保存实际跟拍的完整方案与轮廓；重新生成、撤销选用或切换历史不会改写已经拍摄的快照。快照必须关联现有来源批次和方案。
- 原 schemaVersion=1 增加可选字段；旧数据缺 scene/design/planSnapshot 时保持可读，旧推荐不会被静默重写为新引擎结果。
- 风格偏好存在本机设置，具体推荐风格另存设计快照。默认不增加上传；在线仅随用户主动生成推荐发送原有缩略图。

## 本轮验证状态

开发阶段按用户“后续再 build”的要求只做语法解析；随后用户授权公开照片和模拟器回归，当前已执行完整 Swift 测试、Mac 构建、Simulator 与 iPhone 架构编译，并完成 7 张公开照片的实际像素/持久化流程检查。日期、命令、数量、失败处理见 [验证记录](验证记录.md)，不得将模型夹具和快门替身当真实推理或硬件验收。

Core 测试覆盖知识来源、旧响应退化、视线空间、低光倍率、风格差异、多人、不可信字段、新视角类别轮廓、裁切切边、审核门槛、作业 ID、模型伪造元数据、历史快照，以及风格×主体类别矩阵。App 测试覆盖参考图候选审核/恢复、旧作业拒绝、取消、分割失败保留图片；公开照片回归另覆盖四种调色、原片字节、GPS 剥离、多轮推荐、历史与模拟器相册权限分支。

发现“选用新轮廓却保留旧左右方向/距离提示”后，先用测试复现三个失败断言，再修复并复跑通过。采用生成轮廓时重新根据目标中心输出方向，用重新对照大小替代旧占比的距离推断；UI 与跟拍快照使用修正后的指令。

1. Swift 测试和构建本轮已执行；以后业务变化继续先失败测试再修复、复跑适当检查。
2. iOS 模拟器和 iPhone 架构编译本轮已完成，不能代替真机运行。新 Core 文件由 SwiftPM 自动发现；回归阶段新增 Debug App 检查入口，已从 project.yml 重新生成并检查工程。若后续修改配置，按项目约定同步工程。
3. 模拟器验证风格与历史切换、步骤/来源显示、核对界面三项门槛、取消/重试、撤回选用、滚动和裁切叠加。
4. 真机用人物左右朝向、多人、瓶罐、盒体、平面食物、反光/透明、复杂背景、低光、风景、横图/方图分别验收；先确认模型 scene 输出，再评估知识推荐，最后评估生成图与新轮廓。
5. 对同一组样本保存旧模板基线和 v1 结果，人工盲评建议是否具体、可执行、主体是否完整、风格是否有差异、实际跟拍是否更接近目标。记录原始选择与失败案例，不在没有测量时填写提升率。

本轮尚无“照片变得更好”的实拍证据，亦未训练审美模型、实现人体姿态合成、3D重建、实时对齐或用户反馈训练闭环。这些边界不影响本分支已实现的知识推荐与生成图轮廓选用流程，但不能对外宣传为全场景摄影质量保证。
